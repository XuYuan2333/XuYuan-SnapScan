# XuYuan-SnapScan v1.4.14

Windows 截图识别 / 离线翻译工具：二维码、文字 OCR、截图翻译、手动游戏字幕翻译。
界面为 JadeView 2 + WebView2，模型按需导入，本体不内置大模型。

## 功能

- **截图识码** `Ctrl+Alt+D`
- **截图识字** `Ctrl+Alt+X`
- **截图翻译** `Ctrl+Alt+F`
- **游戏字幕翻译**：只认你画的固定区域（1 个或几个）。区域内所有文字行一次识完；相邻行再按位置并成 2~4 行的段落块，整块翻译、块间并发；字幕换句自动重译，消失自动撤遮罩，**文字没变就不动遮罩**（背景变色、UI 动画都不重译、不闪烁）
- **显示/隐藏译文** `Ctrl+Alt+G`，也可点遮罩上的关闭按钮
- **多 OCR 引擎**：微信 OCR / PP-OCR 极速 / Windows OCR
- **多翻译档**：标准 HyMT1.5、效率 PLaMo Q4_K_M、极速 PLaMo Q2_K
- **模型包导入**：设置 → 识别引擎 / 翻译 → 导入模型包
- **游戏区域悬停预览**：鼠标移到区域行/删除按钮，屏幕上高亮对应区域

## 使用

1. 解压本体到任意目录，运行 `QRSnap.exe`。
2. 设置 → 识别引擎 / 翻译 → 导入模型包，选需要的 zip。
3. `Ctrl+Alt+D` 识码，`Ctrl+Alt+X` 识字，`Ctrl+Alt+F` 翻译。
4. 游戏模式：设置 → 游戏专属配置 → 先画一个识别区域（整屏就框整个画面，字幕带就框字幕）→ 开启游戏模式。
   **开启游戏模式只是「准备」**：不 OCR、不翻译、不上遮罩，也不会自动把翻译服务打开。
   触发方式选「手动」：每按一次 `Ctrl+Alt+F`（或 `Ctrl+Alt+T`）只翻当前画面一次，画面一变遮罩自动消失，不会再自己采样。
   触发方式选「自动」：按 `Ctrl+Alt+T` / `Ctrl+Alt+F` 开/关翻译服务，后台自动识字，字幕换句才重译。
5. PLaMo 只导入 Q4 也能用效率档；需要极速档时再单独导入 Q2 包。
6. 清除 API Key 会自动关闭所有依赖 Key 的 AI 功能。

## 游戏模式：固定区域 + 翻译开关（v1.4.14）

### v1.4.14：删掉「敏感肌」档 + 分块框可视化 + 阈值实测修正

**灵敏度只留 4 档**：低 / 中 / 高 / 极高。原来的第 5 档「敏感肌」（采样 20 / 定住 140 / 巡检 400 / 确认 450）删掉——它和「极高」的差距只有采样 5ms、定住 80ms，实际手感没有区别，反而白吃 CPU。老配置里的 `gamelevel=4` 读进来会夹到 3（极高），下一次保存写回 3。

**阈值是否真的生效（逐条核对）**：

| 参数 | 用在哪 | 结论 |
|---|---|---|
| `GameAutoSampleMs` 采样 | `StartAutoCore` 的定时器周期（夹 20~500） | 生效 |
| `GameAutoHoldMs` 定住 | `AutoTickFixed` 稳定计时（夹 ≥100） | 生效 |
| `GameAutoWatchMs` 巡检 | `StartMaskWatch` 的比对周期 | 生效 |
| `GameMaskConfirmMs` 文字确认 | 遮罩期复核节流 | **原来「无像素变化」那支写着 `Math.Max(1200, …)`，高 1100 / 极高 700 全被抬到 1200，等于这两档在这条路径上没生效**；已改成 `Math.Max(300, …)`，预设值真正落地 |
| `GameWatchMs` 手动比对 | 只在手动模式用（遮罩期像素比对周期） | 生效 |
| `GameAutoDetectMs` 检测间隔 | 没有任何代码读它（只在 ini / BuildState 里转一圈） | **死参数，已删** |

**分块框可视化**：游戏抽屉「灵敏度」下面新增开关「显示分块框（调试）」。打开后，每轮 OCR 完成后在选区上画：粗彩框 = 一个翻译块（带 `#1/#2…` 编号），白色细点线 = 块内每一行的原框，左上角显示「分块 N 个」。窗口是独立的透明分层窗口，游戏窗口本身也是 TopMost 时会定时把自己顶回最前。抓图前自动 `Hide()`、抓完立刻 `Show()`（`BlockDebug.SuspendForCapture/ResumeAfterCapture`），所以框线和编号不会进屏幕抓图、不会被自己的 OCR 读成正文——不能用 `WDA_EXCLUDEFROMCAPTURE`，本项目里分层窗口用它会整块看不见。关闭开关或退出游戏模式立即隐藏。ini 键 `gameblockdebug=1`。

实测（选区 488,277,900,420 精确框住 4 行字幕）：`blocks lines=4 -> 2`，屏上可见 `#1` 单行块与 `#2` 三行合并块，白色点线标出块内每一行。

### v1.4.13：按文字位置并成段落块，整块并发翻译

**不再是「一行一次翻译」**：OCR 出来的每一行本来就带坐标（`OcrSegment.Box`），新增 `GameFilter.GroupBlocks` 在过滤之后再按位置聚一次——同一选区、上下相邻、左右对得上的 2~4 行并成一个段落块，整块送翻译。`ini` 里 `gameblock=1` 默认开，设 0 退回逐行翻译。

判据全部是几何的，避免把任务榜那种多行列表滚成一个大框：

- 行距 ≤ 0.9 倍单行高（`hRef` 只取上一行与当前行较矮的那个，不随合并累加）
- 水平重叠 ≥ 35% 较窄那行；单行高倍率 ≤ 1.8（小字贴大字不并）
- 一块最多 4 行、220 字；上一行已经收句（`.`/`!`/`?`/`。`/`！`/`？`/`…`）时，只有行距 ≤ 0.4 行高且重叠 ≥ 55% 才并
- 不跨分区：`RegionIndex` 不同直接不并

**块之间并发**：预翻译本来就是整批打 `llama-server`，`--parallel 4` 的 4 个槽就是 4 路并发；块数从几十降到十几之后，调用数少一半以上，模型还能看到上一句。顺手把并发阈值从「≥8 行才开 4 路」改成「≥4 块就开 4 路」，并把工作线程数用 `_slots` 卡住（CPU 单槽时不会白开线程往服务端排队）。

实测（4 行对话文本，选区 670×310）：`blocks lines=5 -> 3`，`pretranslate lines=3 hit=2`，前三行并成一块后整段译成一句，出屏正常。

**文字位置/区域识别调研结论**（社区现状）：

- 本项目已经在进程内跑 **PP-OCRv5 的 DB 检测 + CTC 识别**（`PpOcr.cs`，纯 managed + onnxruntime），`Ocr.LayoutSegments` 就是「检测框 → 分行」。官方 speed 表里 `PP-OCRv5_mobile_det` + onnxruntime 端到端 17.9 ms，够用，**不需要再引入 CRAFT/EAST**。
- CRAFT 强在弯曲文本/复杂背景（ICDAR19 ArT F=72.9，VGG16），但后处理复杂、密集场景略逊；EAST 快、适合实时行检测，单字检测有限。游戏字幕是水平短行，DB 检测的边界和速度都更合适。
- 「行 → 段落」没有通用模型，主流做法就是几何聚类：DBSCAN 邻域半径取 0.5×平均行高（*A Deep Learning Approach for Text Segmentation in Document Analysis*）；β-skeleton 图 + 小 GCN 做行聚类（arXiv 2101.12741）；工程库里普遍用「自适应行距 + 垂直邻近 + 组内按 x 排序」再重建段落（npm `kokokor`）。SnapScan 原来的 `MergeLines` 就是这套的简化版，`GroupBlocks` 把「同一句续行」放宽到「同一对话框的 2~4 行」。

### v1.4.11：灵敏度只选档 + 文字没变绝不再收遮罩

**灵敏度改成只选档，不再让玩家填毫秒**：低 / 中 / 高 / 极高（v1.4.11 时还有一档「敏感肌」，v1.4.14 已删）。每档内置一整套阈值（采样间隔 / 定住时长 / 遮罩巡检间隔 / 文字确认间隔 / 手动比对间隔），界面上只留一个下拉框，选完整套生效并写进 ini 的 `gamelevel`。老配置没有 `gamelevel` 时按采样间隔反推最接近的一档，保证界面档位和实际手感对得上；档位越高越跟手，也越费 CPU、越可能多翻一次。

| 档位 | 采样 | 定住 | 巡检 | 文字确认 | 手动比对 |
|---|---|---|---|---|---|
| 低 | 80 | 900 | 2500 | 3000 | 3000 |
| 中 | 50 | 550 | 1500 | 1800 | 2000 |
| 高（默认） | 35 | 350 | 900 | 1100 | 1200 |
| 极高 | 25 | 220 | 600 | 700 | 900 |

**文字没变就跳过「重译 + 收遮罩」**，四处一起改：

1. **长文本不再被 OCR 噪声判成换句**：`TextSimilar` 分两档——40 字以内按 LCS 80% 严格比；超过 40 字改用 3-gram 覆盖率（≥55% 且长度比 ≥55%）。拿实测日志里那对「同一段话的两种 OCR 噪声」回放：旧判据 LCS 判「变了」，新判据覆盖率 0.89 → 判「没变」。
2. **读到自己译文不再算「变了」**：复核抓图时遮罩没掐干净，OCR 会读到这块自己的译文；新增「读到的是译文本身（底图没抓干净），按没变处理」，避免自己的译文把自己判成换句。
3. **只有真贴过译文的区域才有资格收遮罩**：`sl.Lines <= 0` 的分区不参与否决，中文界面区域不会把别人的遮罩收掉。
4. **空壳遮罩不再让巡检空转**：`IsShowing` 只看窗口 Visible，桌面翻译留下的空壳主窗口一直可见 → 遮罩期巡检永远转下去，每隔一秒 OCR 一遍再收遮罩重贴。新增 `TransOverlay.GameShowing`，只认「真的画着东西」的分区（有 items 或成品图），空窗口直接不算，巡检自行停掉。

**复核掐遮罩从 34ms 压到 8ms**：一次复核只丢一帧，配合第 2 条守卫，就算抓到半截帧也不会误收。

**回退 1.4.10 里一条错误优化**：「`_maskUseWin` 为真就用抓窗口那帧底图 OCR、不掐遮罩」——分层遮罩用 `WDA_EXCLUDEFROMCAPTURE` 会连合成一起被剔除（遮罩直接看不见），所以 `ExcludeCapture` 只清成 `WDA_NONE`，屏幕抓图**会**拍到遮罩。那条「复用底图」等于把译文当原文 OCR，稳定误判「文字变了」，已整段删掉。

### v1.4.10：手动/自适应彻底分开 + 不再反复重译

**手动模式之前其实没生效**：按翻译快捷键只是把「翻译服务」打开，而服务一开就走自动采样；遮罩一收，`CloseMask` 又无条件把自动循环拉回来。所以手动和自适应看着一模一样。现在：

- 手动 = 真正的按一次翻一次：`TriggerOnce` 起一轮 OCR + 翻译就停，不注册任何自动采样；遮罩收掉后等下一次按键。
- 手动下遮罩只看像素：按一次看到的就是这一帧，画面一变（区域指纹或整帧判据命中）遮罩立刻消失，不再花 OCR 去复核文字。
- 界面上「游戏翻译服务」开关在手动模式下置灰——那个概念只在自适应里有意义。

**自适应反复闪/反复翻译的三个根因**（都修了）：

1. **采样掐遮罩被当成「遮罩不在了」**：`captureUnderOverlay` 抓底图前会把遮罩隐藏 34ms 左右，`IsShowing` 在这段时间是 false，20ms 的自动采样正好趁这个窗口跑完整轮 OCR + 翻译。新增 `TransOverlay.Sampling`，采样期一律算「遮罩在屏」，堵掉这条重复触发链。
2. **区域基准是上一句的**：`StartMaskWatch` 没清 `_zoneBase`，新一轮第一拍拿旧哈希比当前帧，必然判「区域变了」，然后每隔半秒跑一次 OCR 复核。现在每轮重建区域基准。
3. **文字复核一次抖动就收遮罩**：原来连续三次「和上一句不一样」就收，三次可以是三段不同的 OCR 噪声。现在要连读两次**同一段新文字**才认，`MaskChangeConfirmed` 比对的是两次复核的新文本本身。
4. （1.4.11 已回退这条，见上：分层遮罩会被屏幕抓图拍到，复用那帧等于把译文当原文 OCR。）

**减少翻译调用**：新增跨轮次长缓存（`_preTrLong`，按「翻译来源 + 归一化原文」做键，800 条上限）。同一句原文翻过一次，下一轮直接命中，OCR 抖一两个字也落在同一个键上；以前每轮 `PreTrClear` 之后把所有行重翻一遍。

### v1.4.9：修掉 1.4.8 的启动故障

1.4.8 装上去之后界面像死了一样——按钮点了没反应、热键显示也不对。两处硬伤，都是删「自动识别区域」时留下的：

- **前端脚本语法错**：`web/app.js` 里按行号跳段删除，留了半截 `: "";` 和一个多余的 `}`。JS 是整文件编译的，一处语法错等于**一行都不执行**，所有按钮、输入框、状态回填全部失效。
- **状态 JSON 少一个 `}`**：`BuildState()` 删 `autoRegions` 字段时，把 `game` 对象的收尾括号一起删了。后端吐给前端的 JSON 不合法，前端 `JSON.parse` 直接抛错，界面上全是默认值——热键卡片显示 `Ctrl+Alt+F`（默认值），实际注册的却是你 ini 里的 `Ctrl+Alt+Q`，看着就不对。

修法：补回 `}`、清掉那三行残渣，并且以后改前端都用 `node --check` 过一遍语法、用 `QRSNAP_DBG_STATE=1` 把 `BuildState()` 落盘再用 JSON 解析器校验一遍（工具已经留在程序里，见下面「排查钩子」）。

顺手加固了一处：抓屏区域改成**只抓屏幕内的可见部分**。原来选区有一部分在屏幕外（换过分辨率/缩放以后很容易发生）时，整张 `CopyFromScreen` 会抛「句柄无效」，游戏模式看起来就是「什么都不翻」，日志里刷 `[game] capture fail 句柄无效。`。现在越界只丢越界那条边，日志提示一次 `region outside screen, clipped to visible part`，其余照常识别。

排查钩子（都不影响日常使用，只在设了环境变量时生效）：

| 变量 | 作用 |
|---|---|
| `QRSNAP_DBG_STATE=1` | 把 `BuildState()` 的 JSON 写到 exe 同目录 `_state.json`，用来确认前端拿到的状态是否合法 |
| `QRSNAP_GAME_ON=1` | 启动即进游戏模式 |
| `QRSNAP_GAME_TRANS=1` | 启动即「翻译已开始」（仅测试） |
| `QRSNAP_DBG_ZONE=1` / `QRSNAP_DBG_CROP=1` | 遮罩/裁图落盘 |

### v1.4.8：删掉「自动识别区域」

「自动识别区域」（也叫自适应区域）从 1.4.8 起**整个功能下线**：界面上的开关、ini 里的 `gameautoregion` / `gameautoscope`、以及后台那套「整屏找字 + 轨道跟踪」的检测链路全部移除。原因是它的体验始终不如固定区域：小块裁图太窄，检测模型常把整行漏掉，翻译不全、遮罩也不在文字上。

现在游戏模式只认你画好的固定区域：

- 画 1 个区域（比如整个画面或字幕带）→ 整个区域裁出来跑一次 OCR，识别到几行就翻几行，**不设块数上限**；
- 画多个区域 → 每个区域各自整区识别、各自翻译、各自贴遮罩，互不干扰；
- 没画区域 → 游戏模式不启动，界面会提示先画一个。

### v1.4.8：要不要重画，看文字，不看像素

上一版判断「这块变没变」用的是区域像素指纹：背景换个颜色、UI 有个动画，指纹就会跳，于是遮罩被收掉、重新翻译、再贴回来，屏幕上一下一下地闪。反过来，整页换内容（对话 → 设置页）时因为两页底色接近，像素差异很小，又被判成「没变」，旧译文一直贴在新界面上。

v1.4.8 把判定依据换成文字本身：

- **每轮都识字**，不用上一轮的结论猜；
- OCR 出来的文本与上一轮用容错编辑距离比对（长度差 ≤ 1/6、编辑距离 ≤ 1/8 算同一句）：一致 → 遮罩原样保留，一个字都不重画；不一致 → 这一块才算脏；
- 像素指纹降级为「把这一轮叫醒」的信号，不再能单独撤遮罩；
- 文字真的变了才走「先撤旧遮罩 → 翻译 → 贴新遮罩」，也就是你要的「大变化时先关闭再重新贴」。

### 基础行为

游戏模式只认「固定字幕区域」：画 1 个或几个区域，每个区域整区识别，区域外的 UI、桌面噪声不翻。

**触发方式是两套逻辑（v1.4.10 分开）**：开启游戏模式只做「准备」，不 OCR、不翻译、不上遮罩。触发方式选「手动」时，`Ctrl+Alt+F` / `Ctrl+Alt+T` 每按一次只翻当前画面一次，遮罩出现后画面一变立刻收掉，不会再自己采样；选「自动」时，这两个键才是翻译服务的开/关——按一下开始翻、再按一下关掉，界面开关同步变化，后台按「定住才识字」自动跑。

**不闪屏（v1.4.8）**：遮罩有没有必要重画，只看 OCR 出来的文字。背景换色、UI 动画、采样抖动都不再撤遮罩；文字真的换句 / 消失 / 新出现才收罩重译。同时每轮只做一次整批预翻译，多块在同一轮里上屏。

**灵敏度只选档（v1.4.11，v1.4.14 精简为 4 档）**：游戏抽屉里只有一个「灵敏度档位」下拉框——低 / 中 / 高 / 极高。每档内置采样间隔、定住时长、遮罩巡检间隔、文字确认间隔的整套值（见上表），选完整套生效；想在游戏里调手感，换档就行，不用再琢磨毫秒数字。

**区域内有几行翻几行（v1.4.6 起，v1.4.8 固化）**：固定区域整区识字，不设块数上限。翻译改成「一轮一次整批」：这一轮所有要重翻的文本先合成一批送进引擎，结果按归一化文本缓存，各块随后出屏只差构建遮罩的几十毫秒——实测 9 块整页切换从「5.4 秒一块块冒」变成 **150ms 内全部换上**。

工作方式：

| 环节 | 规则 |
|---|---|
| 采样 | 40ms 采一帧，画面定住 400ms 后才识字（`gameautohold`）；两次识字之间用整区并集的图像指纹挡重复 OCR |
| 识字 | 每个固定区域整个裁出来跑一次 OCR（日文场景额外跑日文模型），识别到的行全部保留 |
| 行合并 | 同一行的框先并成行，再把上下相邻行并成段（字幕两行不会被拆开）；过小/过扁/宽高比反常的框丢掉 |
| 变没变 | 本轮的文本与上一轮做容错比对（长度差 ≤ 1/6、编辑距离 ≤ 1/8 算同一句）。一致 → 遮罩不动；不一致 → 这一块重译 |
| 翻译 | 每轮先 `PreTranslateGame` 把要重翻的文本整批翻好进缓存，各块出屏命中缓存（日志 `[game] pretranslate lines=N hit=M`） |
| 遮罩 | 复用遮罩窗体，内部 96 段小池，不为每个文字块新建窗口；窗口按「区域 ∪ 实际文字行」定位，不会切掉半行 |
限制（都是真的会遇到的）：

- **独占全屏抓不到**：走的是 GDI 截屏，全屏独占或反作弊会截黑，建议游戏用无边框窗口。
- **遮罩期复核有成本**：默认每 0.4 秒对已贴遮罩的区域做一次轻量比对、约 1 秒做一次文字复核，换来「背景不动、只换一行字」也能跟住；嫌吵把 `gamemaskconfirm` 调大即可。
- **桌面上的窗口化测试会被桌面图标、任务栏抢区域**：真全屏游戏里没有这些。
- **整页切换有约 150ms 的重贴窗口**：旧遮罩先收掉、新遮罩陆续画上，这批遮罩是在一个 pretranslate 之后连续生成的，不是一块块等模型。

**换页 / 切 tab（v1.4.8）**：整页换内容时这一块文本必然变，旧遮罩先收掉、整批翻好后再统一贴回，不会出现「旧译文压在新界面上」。

**日文判定会重新复核（v1.4.6）**：中文模型把日文读成满屏汉字时用日文模型复核；整页换语言（日文对话 → 英文设置项）后会重开判定，不会被一次结论锁死（日志 `jp auto on/off`、`jp lost`）。

## 截图 OCR 预处理

预处理不再提供模式选择，固定一套策略，界面上只留一行说明：

| 环节 | 规则 |
|---|---|
| OCR 推理图 | 长边超过 1600 时等比缩小到 1600，再转灰度；长边 ≤ 640 一律不缩放 |
| 预览 / 上传图 | 另起一张彩色图，只做同样的 Lanczos4 缩小，编码为 WebP 90 |
| 增强 | 不做 CLAHE、不做锐化（实测对微信 OCR 无收益，已移除） |

- 缩放两边共用一个系数，禁止拉伸变形；所有缩小统一用自实现的 Lanczos4（a=4，可分离，14 bit 定点权重）。
- 灰度与 Lanczos 都是线性运算，先转灰度再缩放与「先彩色缩放再转灰度」结果等价，但计算量约 1/3。
- **两条独立流水线**：`OcrImage.ForOcr()` 产出推理图，`OcrImage.ForPreview()` 从原图另起一张彩色图。预览图绝不送进 OCR，OCR 结果坐标在 `Ocr.Recognize` / `Ocr.LayoutSegments` 出口按 `PreparedImage.MapBack()` 换算回原图，遮罩对齐不受影响。
- 预览 WebP 由 `cwebp.exe`（libwebp 1.6.0，随包附带）在后台线程编码，落在 `shotcache\preview\*.webp`。WebP 有损（VP8）固定 4:2:0，`-sharp_yuv` 只是让色度更锐，不是真 4:4:4。
